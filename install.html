Aielia/Install
INSTALL · RUN · VERIFY

Install Aielia on your computer.

Three ways to run it: a one-line terminal install, a desktop app, or a browser tab with nothing to install. The terminal and desktop downloads are not code-signed yet, so macOS and Windows will warn you the first time. This page explains why, exactly how to get past the warning, and how to check you got the real thing.

READ THIS FIRST

About the unsigned builds.

Apple and Microsoft each want developers to pay for a signing certificate (and, on macOS, to submit each build for notarization). A signed app tells the operating system who published it and that the file hasn't been altered since. We haven't set that up yet, so for now macOS and Windows treat our downloads as coming from an unknown publisher and show a warning. Linux shows none.

What that does and doesn't mean. The warning is about identity, not about a detected problem: the operating system can't vouch for the file. It is also why you should only bypass it for a file you downloaded from the official places below. Aielia is open source (Apache 2.0), the builds come from a public GitHub Actions workflow, and you can compile it yourself instead (see Verify or build it yourself).

Official sources only: myaielia.com (the install scripts and the release manifest) and github.com/3IVIS/buildaharness/releases. If a file came from anywhere else, don't run it.
Windows 11 and Smart App Control: if Smart App Control is switched On (Settings → Privacy & security → Windows Security → App & browser control → Smart App Control), Windows blocks unsigned programs outright. There is no "Run anyway" button, and the app may simply fail to start without a message. Fresh Windows 11 installs often ship with it on. In that case use the browser version or npx @buildaharness/aielia (Node's own signed program runs the code), or turn Smart App Control off. Turning it off affects every unsigned program on the PC, and on older Windows 11 builds it can't be turned back on without resetting Windows, so check Microsoft's guidance first.

We plan to sign the builds later; when that happens these steps stop being necessary.

TERMINAL

Install the CLI.

The one-liner downloads a standalone binary for your platform, checks its SHA-256 against the release manifest at myaielia.com/aielia-latest.json, and installs it. It uses HTTPS only, won't overwrite an unrelated file, and re-running it upgrades in place.

macOS / Linux
curl -fsSL https://myaielia.com/install.sh | sh
Windows (PowerShell)
irm https://myaielia.com/install.ps1 | iex
  • macOS / Linux installs to ~/.local/bin/aielia (override with AIELIA_INSTALL_DIR). If your shell says command not found, add that folder to your PATH.
  • Windows installs to %LOCALAPPDATA%\Aielia\aielia.exe and adds that folder to your user PATH. Open a new terminal window afterwards.
  • Prefer to read it first? Both scripts are plain text: open install.sh or install.ps1 in your browser before running them.
  • Supported binaries: macOS (Apple silicon and Intel), Linux x64 on a mainstream glibc distribution, and Windows 10/11 x64 (also runs on Windows ARM through emulation). Not supported: 32-bit systems, Linux ARM, and musl-based distributions such as Alpine. On those, use npm, below.
  • The Linux binary is built on Ubuntu 22.04 and needs glibc 2.35 or newer: Ubuntu 22.04+, Debian 12+, Fedora 36+ and similar. On an older distribution (Ubuntu 20.04, Debian 11, RHEL/Rocky 9) you will see GLIBC_2.xx not found; use npm instead.
Why there's usually no warning here: Gatekeeper and SmartScreen check files that a browser or similar app has marked as "downloaded from the internet". curl and PowerShell's irm typically don't add that mark, so a binary installed this way normally runs without the prompt. If you see one anyway, use the manual steps below. This does not help on Windows with Smart App Control on (see above).

First run

shell
aielia --version
aielia

With nothing configured, the first interactive launch asks which provider to use and for its API key (it checks the key with a free read-only call) and saves the choice. Chats, remembered facts and reminders are stored as files in ~/.buildaharness/personal-assistant/. File and command access are off until you turn them on, and every write, command and email waits for your approval.

Already use Node?

shell
# run without installing
npx @buildaharness/aielia

# or install globally
npm install -g @buildaharness/aielia

npm installs aren't affected by the signing warnings at all.

Download the binary by hand

If you'd rather not pipe a script into your shell, download the binary from the aielia-v… release on GitHub. Each file has a matching .sha256 file.

macOS
shell
# check the download against the .sha256 file from the same release
shasum -a 256 aielia-darwin-arm64
cat aielia-darwin-arm64.sha256

chmod +x aielia-darwin-arm64
xattr -d com.apple.quarantine aielia-darwin-arm64
./aielia-darwin-arm64 --version

Use aielia-darwin-x64 on an Intel Mac. If you skip the xattr line, macOS blocks the first launch; then open System Settings → Privacy & Security, scroll to the message about aielia, and click Open Anyway.

Linux
shell
sha256sum aielia-linux-x64
cat aielia-linux-x64.sha256
chmod +x aielia-linux-x64
./aielia-linux-x64 --version
Windows
PowerShell
Get-FileHash .\aielia-win32-x64.exe -Algorithm SHA256
Get-Content .\aielia-win32-x64.exe.sha256
Unblock-File .\aielia-win32-x64.exe
.\aielia-win32-x64.exe --version

Unblock-File removes the "downloaded from the internet" mark. Without it, SmartScreen may say Windows protected your PC: click More info, then Run anyway.

Update and uninstall

shell
aielia update                 # standalone binary
npm update -g @buildaharness/aielia   # if installed from npm

To uninstall, delete the aielia binary (and on Windows the %LOCALAPPDATA%\Aielia folder and its PATH entry). Your data stays in ~/.buildaharness/personal-assistant/ until you delete that folder as well.

DESKTOP APP

Install the desktop app.

Download an installer from the newest desktop-v… release on GitHub Releases, under Assets. It's the same chat UI as the browser version in a native window, with a folder picker for file access and your API key stored in the OS keychain.

macOS — universal .dmg (Intel and Apple silicon)
  1. Open the .dmg and drag Aielia into Applications.
  2. Open it from Applications. macOS will refuse, saying the app is from an unidentified developer or "is damaged and can't be opened". It isn't damaged; that is how Gatekeeper reports an unsigned download.
  3. macOS 15 (Sequoia) and later: open System Settings → Privacy & Security, scroll down to the message about Aielia, click Open Anyway, and confirm with your password. (On older macOS versions you can instead right-click the app, choose Open, then Open again. Don't rely on that on current versions.)
  4. If you only see "damaged" and no Open Anyway button, remove the quarantine mark in Terminal and open the app again:
shell
xattr -dr com.apple.quarantine /Applications/Aielia.app

Only run this on an app you downloaded from the official sources above, and only on that one app. You need to do this once per downloaded version.

Windows — setup .exe or .msi
  1. Run the .exe (or .msi). If Edge or Chrome warns about the download, choose Keep.
  2. SmartScreen shows Windows protected your PC. Click More info, then Run anyway.
  3. Follow the installer, then start Aielia from the Start menu. The app needs Microsoft's WebView2 runtime, which is already part of Windows 11 and up-to-date Windows 10; if it's missing, the installer downloads it, so it needs an internet connection.
  4. If the installer or app does nothing and no warning appears, Smart App Control is probably blocking it (see the note near the top of this page).

Prefer the command line? Unblock-File .\<installer> in PowerShell clears the mark before you run it. A managed work PC may block unsigned installers entirely; in that case use the CLI or browser version, or ask your IT team.

Linux — .AppImage, .deb or .rpm (x86_64)

No warning and nothing to bypass. You need a distribution that ships WebKitGTK 4.1 (libwebkit2gtk-4.1): Ubuntu 22.04 or newer, Debian 12 or newer, or Fedora. The .deb and .rpm pull it in; the AppImage expects it to be installed already. They are built on Ubuntu 22.04, so they need glibc 2.35 or newer; older systems also lack WebKitGTK 4.1, so use the CLI or browser version there.

shell
# AppImage — runs anywhere, no install
chmod +x Aielia_*.AppImage
./Aielia_*.AppImage

# Debian / Ubuntu
sudo apt install ./Aielia_*.deb

# Fedora / RHEL
sudo dnf install ./Aielia-*.rpm

Exact file names carry the version number and may change between releases; use the ones listed under Assets. On Linux the API key is stored with secret-tool (libsecret); install it if the app can't save your key. If the AppImage won't start with a libfuse.so.2 error, install FUSE 2: sudo apt install libfuse2t64 on Ubuntu 24.04 and newer (libfuse2 on older Ubuntu and Debian), or sudo dnf install fuse-libs on Fedora.

Where your data lives

  • macOS: ~/Library/Application Support/com.buildaharness.assistant/
  • Linux: ~/.local/share/com.buildaharness.assistant/
  • Windows: %LOCALAPPDATA%\com.buildaharness.assistant\

Uninstalling the app leaves this folder behind; delete it to remove your chats and settings. The desktop app doesn't update itself yet: to upgrade, install the newer release over the old one.

BROWSER

Or skip installing.

Open myaielia.com/try, paste your AI key in Settings (it stays in your browser), and chat. The browser version is chat only: no file, command or email tools.

TRUST

Verify, or build it yourself.

Checksums. Every CLI binary has a SHA-256 in the manifest at myaielia.com/aielia-latest.json and in a .sha256 file on the release. They come from different places, so they should agree with each other and with the file you downloaded. The install scripts do this check for you.

Build from source. The code is at github.com/3IVIS/buildaharness. The CLI needs Node.js (we build and test on 22); the desktop app also needs a Rust toolchain (rustup, rustc 1.88 or newer).

shell
git clone https://github.com/3IVIS/buildaharness
cd buildaharness
npm ci
npm run build:harness && npm run build:runtime && npm run build:aielia
npm run dev:desktop      # desktop window

A build you compile yourself isn't downloaded from the internet, so it carries no warning.

TROUBLESHOOTING

If it doesn't start.

macOS says the app is "damaged and can't be opened"

It's the unsigned-download message. Run xattr -dr com.apple.quarantine /Applications/Aielia.app and open it again.

There is no "Open Anyway" button

The button only appears after you've tried to open the app once. Try opening it, dismiss the warning, then go straight to Privacy & Security.

Windows shows nothing at all, or the app closes immediately

Smart App Control may be blocking unsigned software silently. See the Smart App Control note near the top of this page for the alternatives.

Windows hides "Run anyway"

Click More info first; the button appears underneath. If there is no such link, your PC is managed and the installer is blocked by policy.

GLIBC_2.xx not found on Linux

Your distribution is older than the one our Linux builds were made on. Use npx @buildaharness/aielia (needs Node.js; we build and test on 22) or build from source.

aielia: command not found after installing

Open a new terminal. On macOS/Linux make sure ~/.local/bin is on your PATH; on Windows the installer updated the user PATH, which only applies to new windows.

The installer refuses to overwrite aielia

Something else (often an npm-linked aielia) is already there. Remove it, or re-run with --force (curl … | sh -s -- --force; on Windows set $env:AIELIA_FORCE = '1' first).

The Linux desktop app can't save my API key

Install libsecret-tools (provides secret-tool) and make sure a keyring service such as GNOME Keyring is running.

Still stuck? Open an issue on GitHub with your OS, which download you used and the exact message.
